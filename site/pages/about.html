About

Local models on hardware you own, with the evidence attached.

Xyntetik is the program under which Zenova AB builds tooling for running capable language models on ordinary laptops, desktops and workstations, and for proving what those models did. Runner is its released engine and Dojo its released desktop app. Four more parts exist and are described here as what they are: three private apps, Suite, Bocka and Lunta, and a research lab, Shade.

Why Xyntetik exists

The engine is the easy half.

Serving tokens from a GGUF file is a solved problem. What is not solved is everything between a running model and work you would actually trust: choosing a model that fits the machine instead of one that swaps, giving an agent tools without opening a hole per tool, keeping a human in the loop without making them a bottleneck, proving a change works rather than reporting that it was written, and keeping a record of where every claim came from. Xyntetik is a program for that whole distance, built in the order the evidence allows. Dojo is the first piece of that distance to ship beside the engine: the window the agents and the local model are worked from.

{{mark:runner:44}}

Runner

Execution and inference runtime. A single binary in plain C that serves, verifies, scores, quantizes, adapts and trains GGUF models on CPU, CUDA and Metal. Receipts, truncation-safe tool calls, LoRA through the served weights.

released, Apache 2.0

{{version}}, {{release_date}}. Public repository, releases with checksums, every claim measured. The one part of Xyntetik whose job is to be understood by a stranger in sixty seconds.

Dojo

One window for your coding agents. A macOS app that runs Claude Code, Codex and pi on a local Runner model as terminal panes, here or over SSH, with a bus so they can list, read and message each other while you watch.

released, Apache 2.0

Public repository, SwiftPM only, three commands to install. The bus never answers a prompt and never sends your half-written text; every message carries its sender from the pane's token.

{{mark:suite:44}}

Suite

One desktop app around the engine. A Rust application for Windows, macOS and Linux in place of nine Python packages and seven local services: an agent, a memory vault, tasks, an approval queue, coding workflows and Runner control in one process. Nothing of it listens on the network; only the Runner does, on loopback.

private, first release 0.1.0

The first release, 0.1.0, is private, for the owner and named testers, with installers that carry no publisher signature yet. 1.0.0 will be the public one, and Suite gets its own public section then.

Bocka

One plan that a person and their coding agents both work from. A plan of record in a folder you choose, one small file per item, read and written by a macOS window and a bocka command. Agents claim items with a lease, ask the owner with the recommended answer first, and close an item only with its proof.

private, in use

Private repository, no download. It holds the plan this program is built from, and gets a public section when it has a public repository.

Lunta

A writing app for long-form fiction. Novels and screenplays: an outline, chapters and scenes, a lore bible, the story's through-line tracked from scene to scene, and a co-writer.

private, in development

Private repository. The design is an interactive mockup, and the app is being built from it: the core library and the project format first, then the command, then the Mac app.

{{mark:lab:44}}

Shade

Experimental research into models, architectures and inference. Quantization, pruning, sublayer removal and evaluation methodology, run under a written charter: preregistration before measurement, corrections recorded in place.

research, experimental

Private repository. Its public outputs are model artifacts and evidence datasets on Hugging Face, grouped into collections, and engine features that graduated from a finding. Shade discovers; Runner productizes.

How they relate

The engine measures. The suite decides. The lab finds what the next measurement should be.

Shade finds a mechanismA study removes one attention sublayer from a 31B model and measures what it costs against the parent on a held-out split.
Runner productizes itThe finding becomes --remove-sublayer in Runner, with a bit-identity gate against the study's zeroed form, and the artifact is published with its numbers.
Suite puts it in front of a personThe desktop app finds and checks the Runner, offers the release it pins, and keeps an approval queue and an audit journal around what agents do. Admitting or refusing a derivative for one machine and workload, with the receipt kept, is not built yet.

Nothing crosses that pipeline without a measurement, and a measurement that goes the wrong way is published as a negative result rather than dropped. Two consequences follow. The audience arbitrates every ambiguous decision: what makes a local model usable on a modest machine wins over what is architecturally interesting. And correctness is a hard rule rather than a preference, because everything else relies on it; a faster wrong answer is a regression.

Rules for public claims

What you can hold this site to.

Every number has a date and a document

Measurements say when they were taken and on what, and link to the file in the repository or the card on Hugging Face where the raw material lives.

Claims are scoped to what was measured

A comparison covers the engines and versions that were run, not the ones that were not. A training result covers the base and task it was measured on. Titles may say "deterministic"; the claim text says reproducible on the same build, with the edges written down.

Losing rows stay in the table

Prefill throughput, cold time to first token, MoE decode on GPU, a published artifact that missed the bar: all on the evidence page, with the number.

The site cannot outrun the repository

The site source lives in the public Runner repository and is built from it; the footer names the commit. If this site and the README disagree, the README is right and the site has a bug.
