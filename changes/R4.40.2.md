- **On CUDA, a phi3 LongRoPE model's factor set follows the sequence, as on the CPU and the Apple GPU** (R4.40.2).
  - The cost, first: past the original context, several slots of one such model no longer decode as one device microbatch on CUDA; they decode one by one, as on Metal. On an RTX 5070 host with bartowski's Phi-3.5-mini-instruct Q4_K_M, four short requests at once (`--parallel 4 -c 8192 --kv q8`, 256 tokens each, all 32 layers on the device) decode at 162.7 tok/s aggregate, where the build before read 350.0 with every slot on the long set (median of three rounds each). A single slot decodes as before.
  - What changes: with `-c` over the original context (4,096 tokens on Phi-3.5) CUDA kept the long factors for every sequence and warned so at load, because the rope table belonged to the weight set every slot shares. The weight set now holds both sets' tables and each slot reads its own: a sequence within the original context computes what a load at it computes, a longer one takes the long set from its first token, and a sequence that grows past it is computed again under the long set, once. On that host the Q4_K_M at `-c 8192` scores a 317-token text bit for bit as at `-c 4096` (the build before differed), an 8,051-token text bit for bit as the build before, and a served prompt of 4,044 tokens that grows to 4,120 is computed again once, after which the same prompt keeps nothing (`prompt_reuse` `rope_set`) and answers as a fresh request.
  - The decode graph holds the table it was captured with, so a slot that changes set captures it again: once at the crossing, once on the way back.
  - Rows an earlier CUDA build saved for such a load (the prefix cache, KV snapshots) are refused: on CUDA too the cache key of a two-set load now carries the per-sequence token R4.40.1 gave it on the CPU and Metal.
  - Gated by `make test-cuda-longrope`, a `scripts/cuda-gate.sh` step: the LongRoPE gate on the device, every comparison CUDA against CUDA to the bit, with live controls (the two sets differ on the device; a decode graph kept across a set change is caught). `tests/test_phi3_rope.py` serves the crossing on CUDA and joins the CUDA lane.
