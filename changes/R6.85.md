- **A Windows build takes the portable math by default, so one `runner.exe` gives the same reply on every Windows host** (R6.85).
  - **Limits first:** Windows replies change once. The same prompt can give a different reply from this release on than from 1.20.0 and before, because the last bits of every `exp` and `log` change. On the RTX 5070 host the portable build matched 27 of the 29 Windows CPU cells' pins; `minicpm5-2b-q4_k_m` and `trinity-nano-preview-q8_0` moved, and their Windows pins are recorded again from this branch's release build (the other 27 match). Linux and macOS are unchanged. A Windows build is still not a T3 build (fast-math and each ISA's own reduction order stay), so it agrees with Linux and macOS on sampled tokens, not on the last bits.
  - **Why:** a default Windows build called the C runtime's `expf` and `logf` under `-ffast-math`, and `ucrtbase` versions differ in the last bits. The published 1.7.1 and 1.20.0 binaries gave a different trinity-nano reply on the RTX 5070 host than the pin recorded on another Windows host: same build, different bytes.
  - **Cost:** the prompt cost of the portable math was within the owner's 5% line on each of three files at both ISAs (the RTX 5070 host, R6.86's 580042ac, 2026-11-18).
  - **Which math a binary has:** `runner --caps` and the server's build fields (`/health`, `/v1/capabilities`, `/v1/provenance`) answer `"math": "portable"` or `"math": "libc"`, so a Windows build and its opt-out can be told apart. `runner --version` is unchanged, because a release compares that line exactly.
  - **What stays:** `make PORTABLE_MATH=0` builds the C runtime's math, as before. `make PORTABLE_MATH=1` opts in on Linux and macOS. The switch is applied with `override`, so a release that sets `CFLAGS` on make's command line still takes it.
  - **Also fixed:** `scripts/check-sample-nan.sh` read only a binary that names itself `default`, so in a portable default build it found no digest and failed. It now reads each binary's own digest line, and fails if the default build prints none.
  - **Tests:** `tests/test_ci_contracts.py` (the sampler check passes with `PORTABLE_MATH=1`, built as a Windows default is; and a Windows compile line takes `src/pmath.h` by default and with the release's flags, `PORTABLE_MATH=0` opts out, Linux and macOS do not; it failed before this change). The Windows CI job runs `make test-portable-imports` at the release's own flags: no object imports `expf`, `logf`, `sinf`, `cosf`, `tanhf` or `powf`.
