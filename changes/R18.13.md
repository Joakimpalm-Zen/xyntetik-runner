- **Linux loads now prefault cached host-used weight ranges into process page tables (`MADV_POPULATE_READ`), protecting mapped weights under multi-gen LRU with no change under the classic two-list LRU** (R18.13).
  - Measured on `LFM2.5-8B-A1B-Q4_K_M.gguf` (5.16 GB public MoE, cgroup `MemoryHigh` reclaim between load and Prompt 1): under multi-gen LRU (`mglru`), `main` dropped to 0.613 resident / 4,987 first-prompt major faults / 4.56 s in run `45907096696` and 0.613 / 5,153 in run `45908741348`, while default `cached` and `full` held 1.000 resident / 0 major faults across all three runs (0.77 s first prompt; generating during pressure 1.000 / 0). Under classic two-list LRU (`classic`), mapped pages are still reclaimed under sustained pressure: run `45907096696` read `cached` 0.621 / 4,971 (`smaps` Rss 4,917 to 3,054 MB) and `full` 0.618 / 5,829 (slightly worse than ~4,900 on `main`); run `45908741348` confirmed no harm (`cached` 0.619 / 5,252 vs `main` 0.613 / 5,220), parity with `llama.cpp` `56eea9e4b` (0.000 / 8,143), and eviction even while actively generating (0.616 resident, `smaps` 4,917 to 3,010 MB, 2,692 during-pressure major faults). In the same `Q4_K_M` cgroup harness under MGLRU, `llama.cpp` (`56eea9e4b`) also lost pages (0.628 resident, 42,678 first-prompt major faults, `smaps` 3,060 MB), likely confounded by x86 `Q4_K` CPU repacking into anonymous buffers and host swap rather than testing a repack-free file with swap off.
  - Default mode (`RUNNER_POPULATE=cached`, unset, `1`, `on`): runs `mincore(2)` first and calls `madvise(MADV_POPULATE_READ)` (with `EINTR` retry and an `EINVAL` page-stride read fallback on kernels before 5.14, and without `MADV_SEQUENTIAL`) only over contiguous runs already in the page cache, adding zero disk I/O on cold loads. Per Linux kernel commit `134fca9063ad` (`can_do_mincore`), when the caller neither owns the file nor has write permission (such as a root-owned read-only model), `cached` skips the pass, stays lazy, reports why on the load line, and never falls back to `full`. `RUNNER_POPULATE=full` opts into a blocking full populate (`MADV_SEQUENTIAL` + `MADV_POPULATE_READ` + `MADV_NORMAL`; slightly worse under classic LRU on one run: 5,829 vs ~4,900 major faults); `RUNNER_POPULATE=0` or `off` disables it (`MANUAL.md`). Each Linux load with host-used ranges prints a `populate:` line naming the mode, the kernel's LRU mode from `/sys/kernel/mm/lru_gen/enabled` (`[mglru]` or `[classic]`), bytes mapped, bytes left lazy, and elapsed seconds.
  - Populates only host-used weight ranges with zero heap allocations during load: skips the GGUF header prefix (`gguf_map_data_offset`), header-only (`--info`) paths, device-resident loads (full CUDA, Metal, and whole-CUDA Inkling 2 `'W'`, which `model_weights_on_device()` now also recognizes), `--mlock`, oversubscribed `--moe-prefetch`, and repeat `--parallel N` slots (populated once per loaded file for both shared `m->W` and unshared Inkling 2 instances, keeping `VmPTE` at 1x). Under `--cpu-moe` (generic CUDA and Inkling 2 CUDA `'M'`), populates only host-computed expert stacks (excluding `RUNNER_MOE_HOT` VRAM experts) and any CPU-side layers.
  - **Cgroup v2 `memory.high` is now folded into `plat_ram_available_bytes()`** (`src/compat.c`, `tests/test_capacity.c`): `cg_fold()` reads both `memory.max` and `memory.high` across every ancestor cgroup level (alongside cgroup v1 `memory.limit_in_bytes`) and bounds available RAM headroom by the tighter of host `MemAvailable` and the cgroup's effective limit while leaving `memory_max_bytes` as the hard ceiling.
  - Guarded by `tests/test_populate.c` (mode parsing, kernel LRU mode parsing, `mincore` trap, load-line formatting, host range selection, header/device skip, and Linux `/proc/self/smaps` Rss checks), `tests/test_capacity.c`, `tests/test_model_load_oom.c`, `tests/test_doc_counts.py` (`POPULATE` owned by `substrate` in `scripts/capability-inventory.py`), and the real-file cgroup `memory.high` parity check `scripts/r1813-reclaim-check.sh`.
