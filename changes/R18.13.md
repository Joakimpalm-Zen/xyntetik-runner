- **Linux loads now prefault cached host-used weight ranges into process page tables (`MADV_POPULATE_READ`) so mapped weights are no longer first-pass reclaim victims** (R18.13).
  - Previously, Runner mapped GGUF files lazily (`PROT_READ | MAP_PRIVATE`) without installing page-table entries at load, so untouched embedding and MoE expert pages sat unmapped (`referenced_ptes == 0`) on `inactive_file`, where Linux's `folio_check_references()` reclaims them on the first pass even with `PG_referenced` set (losing up to 3.7% of Inkling 2 Mini's 22.87 GB mapping under reclaim while `llama.cpp`'s `MAP_POPULATE` stayed >= 0.9995 resident).
  - Default mode (`RUNNER_POPULATE=cached`, unset, `1`, `on`): runs `mincore(2)` first and calls `madvise(MADV_POPULATE_READ)` (with `EINTR` retry and an `EINVAL` page-stride read fallback on kernels before 5.14, and without `MADV_SEQUENTIAL`) only over contiguous runs already in the page cache, adding zero disk I/O on cold loads. Per Linux kernel commit `134fca9063ad` (`can_do_mincore`), when the caller neither owns the file nor has write permission (such as a root-owned read-only model), `cached` skips the pass, stays lazy, reports why on the load line, and never falls back to `full`. `RUNNER_POPULATE=full` opts into a blocking full populate (`MADV_SEQUENTIAL` + `MADV_POPULATE_READ` + `MADV_NORMAL`); `RUNNER_POPULATE=0` or `off` disables it (`MANUAL.md`). Each Linux load with host-used ranges prints a `populate:` line naming the mode, bytes mapped, bytes left lazy, and elapsed seconds.
  - Populates only host-used weight ranges: skips the GGUF header prefix (`gguf_map_data_offset`), header-only (`--info`) paths, device-resident loads (full CUDA, Metal, and whole-CUDA Inkling 2 `'W'`, which `model_weights_on_device()` now also recognizes), `--mlock`, oversubscribed `--moe-prefetch`, and repeat `--parallel N` slots (populated once per loaded file for both shared `m->W` and unshared Inkling 2 instances, keeping `VmPTE` at 1x). Under `--cpu-moe` (generic CUDA and Inkling 2 CUDA `'M'`), populates only host-computed expert stacks (excluding `RUNNER_MOE_HOT` VRAM experts) and any CPU-side layers.
  - **Cgroup v2 `memory.high` is now folded into `plat_ram_available_bytes()`** (`src/compat.c`, `tests/test_capacity.c`): `cg_fold()` reads both `memory.max` and `memory.high` across every ancestor cgroup level (alongside cgroup v1 `memory.limit_in_bytes`) and bounds available RAM headroom by the tighter of host `MemAvailable` and the cgroup's effective limit while leaving `memory_max_bytes` as the hard ceiling.
  - Guarded by `tests/test_populate.c` (mode parsing, `mincore` trap, load-line formatting, host range selection, header/device skip, and Linux `/proc/self/smaps` Rss checks for `cached` warm/cold, `full`, `off`, `mincore` trap, `--parallel 2`, and tight `memory.high`), `tests/test_capacity.c`, and the real-file cgroup `memory.high` verification script `scripts/r1813-reclaim-check.sh`.
