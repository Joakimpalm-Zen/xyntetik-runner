- **Linux loads now prefault host-used weight ranges into process page tables (`MADV_POPULATE_READ`) so mapped weights are no longer first-pass reclaim victims** (R18.13).
  - Previously, Runner mapped GGUF files lazily (`PROT_READ | MAP_PRIVATE`) without installing page-table entries at load, so untouched embedding and MoE expert pages sat unmapped (`referenced_ptes == 0`) on `inactive_file`, where Linux's `folio_check_references()` reclaims them on the first pass even with `PG_referenced` set (losing up to 3.7% of Inkling 2 Mini's 22.87 GB mapping under reclaim while `llama.cpp`'s `MAP_POPULATE` stayed >= 0.9995 resident).
  - After binding weights on Linux, `model_populate_weights()` now runs `plat_populate_ro()` (`MADV_SEQUENTIAL` -> `madvise(MADV_POPULATE_READ)` with a page-stride read fallback on kernels returning `EINVAL` -> `MADV_NORMAL`) over only the host-used ranges: skipping the GGUF header prefix (`gguf_map_data_offset`), header-only (`--info`) paths, device-resident loads (full CUDA, Metal, and Inkling 2 CUDA `'W'`), `--mlock`, oversubscribed `--moe-prefetch`, and repeat `--parallel N` slots (populated once per loaded file for both shared `m->W` and unshared Inkling 2 instances). Under `--cpu-moe` (generic CUDA and Inkling 2 CUDA `'M'`), only host-computed expert stacks (excluding `RUNNER_MOE_HOT` VRAM experts) and any CPU-side layers are populated. Set `RUNNER_POPULATE=0` or `off` to opt out (`MANUAL.md`).
  - Cgroup memory headroom in `plat_capacity_at()` / `plat_ram_available_bytes()` now folds cgroup v2 `memory.high` alongside `memory.max` (and cgroup v1 `memory.limit_in_bytes`) across every ancestor level so populate never exceeds the tighter of host `MemAvailable` and the cgroup's effective limit. `model_weights_on_device()` now also recognizes whole-CUDA Inkling 2 loads.
  - Guarded by `tests/test_populate.c` (policy, range selection, header/device skip, and Linux `/proc/self/smaps` Rss checks), `tests/test_capacity.c` (cgroup v2 `memory.high` headroom checks), and the one-command real-file cgroup `memory.high` reclaim check `scripts/r1813-reclaim-check.sh`.
