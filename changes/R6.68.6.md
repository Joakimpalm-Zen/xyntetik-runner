New libFuzzer harnesses: `tool_stream`, the demultiplexer that reads a model's own turn and separates prose from tool calls, with the property that a turn fed one byte at a time and fed in chunks gives the client the same reasoning, content, calls and result, on every template family; `record_check`, the verifier a third party runs on a signed receipt or record it did not write, in memory and through the file path; and `session_read`, the reader of a session image that travels between machines, with the SHA-256 trailer fixed up so the mutator reaches the parser behind it. A new `fuzz soak` workflow runs every registered target for a chosen number of seconds each (by dispatch, and weekly), starting from the corpora the daily run has evolved; a red weekly soak opens the same issue a red daily run does. Before CI ran them, 24,000 mutated turns and 12,000 mutated records and images each passed under ASan and UBSan through the replay driver.
