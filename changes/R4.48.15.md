- **Inkling 2 Mini: a fast CPU route** (R4.48.15, work in progress).
  - **Limits first:** the fidelity bar, the thread-invariance read, the 8-bit control and the speed against llama.cpp on the real files have not run yet; until they do, no number here is a claim about the real model. The tests, written before the route: `tests/test_inkling2_fast.c` (the route switch, closeness to the reference route without equality, thread and batch-width invariance, no float32 weight copies, and an 8-bit activation control that must fall further from the reference), `tests/test_nvfp4_dot.c` (a SIMD NVFP4 dot, its decode bit for bit, its accuracy, its multi-column twin) and `tests/test_inkling2_fast.py` (`--info fit` naming the route). They fail until the route lands.
  - `tests/inkling2_tiny.py` writes the tiny inkling2_loop file with its dense projections F32, BF16 or Q8_0, so every weight type a real file carries reaches the engine; the loader's hardening test takes it from there.
  - **NVFP4 gets SIMD kernels:** the dot and the prefill tile's decode on AVX2 + FMA and on NEON (the scalar loop stays for other builds). The dot keeps float32 activations, takes the E2M1 codes through a byte shuffle and each sub-block's UE4M3 scale from a table, and sums the even and the odd sub-blocks in two accumulators; it is within 1e-7 of a double-precision dot. The decode gives the scalar decode's bits for every code at every scale.
  - **The route:** `RUNNER_INKLING2_ROUTE` (`fast` by default, `reference` for the admission's serial float32 engine). On the fast route the GGUF source serves the projections, the head, the embedding and the expert stacks as views of the stored rows (`ink2_tensor.q`: the file's type, its row stride, a stack's per-expert `.scale`), never decoded, and the engine's one linear operation (`ink2_lin`) runs them with the CPU kernels: float32 activations, the weights decoded in registers, threads over output rows, each column the single-column dot's bits whatever the batch. The experts of a chunk run grouped by expert, each position's sum in ascending expert order as the reference adds it; an expert's factor applies after its dot. Norms, taps, queries, scales and the router stay small float32 decodes. On the exact file at 8K, `--info fit` reads 22.21 GiB against the reference route's 32.17 (no float32 matrices, no expert cache). The reference route is the admission's code unchanged.
