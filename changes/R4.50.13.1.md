- **The validated list notes three publisher files whose GGUFs type ordinary tokens as control tokens** (R4.50.13.1).
  - `docs/model-support.md` now carries the defect under Known limitations for each of the three rows.
    `docs/model-tiers.json` holds the text and `scripts/model-tiers.py --write-docs` renders it.
  - unsloth's Olmo-3-7B-Think Q8_0 types id 5809, U+FFFD (the replacement character), as a control token, where
    the publisher's `tokenizer.json` has it as a normal token. Runner never shows the character in output, JSON
    mode and JSON schemas cannot produce it, and text that holds it is tokenized differently from the publisher's
    tokenizer.
    - Runner does not repair it, because the file also rewrote the token's string. The load-time repair added in
      R4.50.13 covers only tokens whose string is a merge output.
    - unsloth's BF16 and UD-Q4_K_XL carry the same defect. bartowski's GGUFs of the model type the token as a
      normal token.
  - LiquidAI's LFM2.5-350M Q4_K_M and Q8_0 type "python" (id 64014) and "Mathias" (id 64011) as control tokens,
    where the publisher's `tokenizer.json` has them as ordinary tokens. On 1.22.0 both words drop from output, and
    JSON mode cannot produce them.
    - Releases after 1.22.0 repair both at load (R4.50.13) and name them in a load line. `RUNNER_TOK_REPAIR=0`
      keeps the file's types.
  - Known limits: the Olmo-3-7B-Think row keeps the defect until a correct conversion replaces the file, and the
    notes describe the files as pinned, not later uploads.
