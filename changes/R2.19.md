- **A bounded number is never led past its bound** (R2.19).
  - Under `{"type": "number", "maximum": 1}` the validator admitted `1e+36`. After it no byte was legal, so a constrained request stalled with every token masked, and a forced close wrote `1e+36`, out of bounds. A real output showed it: `2.74e+57` under a maximum of 10, in the JSONSchemaBench corpus.
  - Now a number's prefix is admitted only while some completion of it lies inside the bounds, so the byte that would leave none is refused where it is written: the `3` of `1e+3` under maximum 1, or a first digit no scale brings inside a narrow interval (under `[0.5, 0.6]` a number cannot start with `1`). The question is decided exactly, in decimal: the bounds become the exact interval of the spellings that read inside them (the midpoints to the neighbouring doubles, built once per schema), and a prefix is compared with it digit by digit, with no floating-point arithmetic. The answer is the same on every platform and in every float mode, completions that read as exactly a bound count (`4.9999999999999999e-1` under `[0.5, 0.5]`), and a forced close writes the shortest completion inside.
  - A number is spelled in at most 95 characters, the most the validator keeps, so a completion must fit in what is left: under `maximum: 1`, 91 nines are the most it admits (`e-91` completes them), and a point or an exponent mark is refused at the 95th byte, where its digit has no room.
  - Under a bound, a number whose value lies below the smallest normal double (0 < |x| < 2^-1022, about 2.2e-308) is now refused, at both signs. The parsers disagree there: glibc reports a range error for most of that range, macOS's parser rounds the top of it up to 2^-1022 and accepts it, Windows' accepts subnormal values, and a flush-to-zero float mode compares a subnormal as 0. Refusing it gives one answer on every platform. Unbounded numbers are unchanged.
  - Under an inclusive `minimum: 0` a number may now start with a minus sign, since `-0` is 0. The minus used to be refused under every minimum of 0 or more; under an exclusive 0, or a positive minimum, it still is.
  - Checked against an independent exact reference with bounds drawn at random (narrow, points, next to 2^-1022, one-sided, strict and inclusive, both signs) on macOS, Linux and Windows, with flush-to-zero off and on: over 10,000 random bounds, 65,575 admitted prefixes completed inside, 70,707 refused bytes had no completion, and 51,093 whole numbers were judged as the definition does. Every platform and float mode gave the same answers.
