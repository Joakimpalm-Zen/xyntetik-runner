- **The runner's own `expf` (`src/pmath.h`, the portable math of a `T3=1` build) no longer keeps the attention softmax's loop scalar, and gives the bits it gave before** (R6.86).
  - Exactly what "the bits it gave before" covers:
    - under strict float (a T3 build): every one of the 2^32 float inputs, NaNs included;
    - under `-ffast-math` (a portable build of the default flags, `-DRUNNER_PORTABLE_MATH`): every float that is not a NaN.
    - For a NaN it gives the strict build's answer, the input NaN. For a quiet NaN that is also the C library's answer, so at its callers a portable build answers a NaN as the default build does. The old `expf` had no defined answer there; on Apple clang it gave +0.
  - Limits:
    - A T3 build's output does not change, and neither does a default build's, which does not use this header.
    - A portable build of the default flags can move in its last bits: its softmax loop now vectorizes, and a vector loop adds the sum in another order.
    - The Windows default is unchanged here. Whether it takes the portable math waits for a read on Windows (R6.85).
  - Why: on Windows, where the C runtime's `expf` varies by Windows version, a portable build was 8 to 15% slower on a prompt than the default (R6.85). The portable `expf` was `(float)pm_exp_d((double)x)`, and `pm_exp_d`'s early returns and the loops of its power-of-two scaling kept the softmax's exp loop scalar.
  - What: `p_expf` now has no branch and no loop. For a float input `pm_exp_d`'s guards decide nothing: below -104 the float is +0, above 89 it is +inf, and in between the power of two is one exponent store. So x is clamped to [-104, 89] and the same operations run in the same order. A NaN is picked out by a test on its bits, not by a float compare that `-ffast-math` may fold away. `pm_exp_d` is unchanged, as are `tanhf` and `powf`, which use it.
  - Checks:
    - `tests/test_pmath_expf.c` compares the new `expf` with the old one bit for bit, in a vectorized buffer loop and in a scalar call. Its inputs:
      - 60 named inputs: the signed zeros, the infinities, nine NaNs of both signs with payloads, the subnormals, both clamp edges and their neighbours, the overflow and underflow edges, `pm_exp_d`'s own guards and loop crossings, and the ties of k's rounding;
      - every 256th bit pattern.
    - It holds a mutant as a live control: a copy with the low half of ln 2 set to 0, whose errors stay inside the 1-ulp accuracy bound. The sample tells it from the old function at 27,035 inputs.
    - Under the default flags its NaN answers are held to the strict build's: the old function compiled under strict float in a unit of its own, linked in.
    - `make test` runs it under both flags, on the 60 named inputs and the 2^24 sampled bit patterns. The two all-floats targets are opt-in: `make test-pmath-expf-all` (strict) and `make test-pmath-expf-all-default` (the default flags), about a minute each.
    - `tests/test_pmath_callers.c` (`make test-pmath-callers`, in `make test`) builds the engine's sampler and softmax (`src/softmax.h`, moved out of `src/model.c` unchanged) with the default flags and as a portable build of them. For five NaNs the two must decide the same: the token, and whether each output is a NaN or which finite value it is.
    - `make test-pmath-vec` reads the compiler's own vectorization report for `src/model.c` in a portable build of the default flags. It requires both softmax exp loops to be vectorized and reports the prompt FFN's SwiGLU loop. `make test` runs it with Linux gcc; the macos and windows CI jobs run it with Apple clang and MinGW gcc.
    - `make bench-pmath-loops` times those loops with the old and the new `expf`, interleaved.
  - **Red first, the NaN:** in a portable build of the default flags, the first version of this change gave +inf for a quiet NaN. `sample_pick` with logits [0, NaN] and top_k 2 then picked the NaN token at every RNG state, where the default build picks the finite one. `softmax_sink` with a NaN sink gave finite zeros where the default build gives NaNs. `test-pmath-callers` and the default-flags compare were red on that; both are green now.
  - **Red first, on CI's three compilers:** on main's `expf`, `test-pmath-vec` failed with Linux gcc 15.2, MinGW gcc 16.2 and Apple clang. Neither softmax loop was vectorized. The SwiGLU loop was vectorized already by MinGW gcc (64-byte vectors) and by neither of the others.
  - **Gated**, on an Apple M1 (Apple clang 21):
    - All 2^32 floats, under strict float and under the default flags: none differs, the 16,777,214 NaNs included (under the default flags, against the strict build's answer).
    - On main the compiler gave the softmax loops no remark at all, since the scaling loops inside made them outer loops. After the change both are vectorized at width 4, interleaved 4. The SwiGLU loop is scalar on clang in both, because the activation switch's GELU branches are not unswitched.
    - `bench-pmath-loops`, 15 interleaved rounds: the softmax loop is 2.36x as fast (lowest round 2.02x), a SiLU loop 2.24x.
    - T3 runners from main and from this change give byte-identical `--score` files and greedy generations on the four test fixtures and on SmolLM2-1.7B-Instruct Q4_K_M.
