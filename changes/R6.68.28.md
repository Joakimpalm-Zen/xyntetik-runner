- **Two fixes found while the architecture rules moved into one table** (R6.68.28, R6.68.36): a rope base clang builds read from the wrong key, and adapters the merge refused although `--lora` served them.
  - **A file that names its sliding layers' rope base `rope.local.freq_base` now gets that base on every compiler** (R6.68.28, found in the full sweep): the loader read `rope.local.freq_base` and its fallback `rope.freq_base_swa` in one call, both spelled into the same key buffer, so the order a compiler evaluates arguments in chose the key. A clang build (every macOS build) read `rope.freq_base_swa` for both and roped the sliding layers at the wrong base whenever a file declared the two with different values. The reads are now made one at a time, and `test-rope-yarn` loads a fixture that declares 500 and 20000 and holds the sliding table to 500.
  - **`--merge-lora` folds a Gated DeltaNet adapter into a qwen35moe or qwen4exp model** (R6.68.36): serving applied an adapter's DeltaNet projections (`in_proj_qkv`, `in_proj_z`, `in_proj_b`, `in_proj_a`, `out_proj`) on every DeltaNet family, while the merge accepted them on qwen35 and clef only and refused the same adapter on Qwen3.5/3.6-35B-A3B-shaped and qwen4exp files ("targets a projection this model does not carry"). The merge now reads the family from the same table serving does. `test_lora_qwen35` merges such an adapter on both toy fixtures and holds the merged file to the adapter at load time and to the reference the fixture writer folds.
