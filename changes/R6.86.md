- **A `make T3=1` build replaces the C library's `expf`, `logf`, `sinf`, `cosf`, `tanhf` and `powf` in every unit, as MANUAL.md says it does** (R6.86).
  - The portable versions in `src/pmath.h` were put in by macro, so they reached only code the compiler read after that header. In `src/model.c` the activations' header and the model header came first. `src/cuda.c` and `src/clef.c` never read it. So SiLU and sigmoid, softplus, the attention temperature, CUDA's host-side MoE router softmax and Clef's softmax kept the C library's functions, whose last bits differ by platform.
  - A portable build (`T3=1`, or `-DRUNNER_PORTABLE_MATH` in CFLAGS) now has the compiler read `src/pmath.h` first in every unit, and so does `make cross-riscv64`. The header's system includes now come before a source's own feature macros, so the two `compat.c` sets (`_GNU_SOURCE` on Linux, `_CRT_RAND_S` on Windows) are given on the command line too.
  - `make T3=1 test-portable-imports` reads every object `runner` links with `nm -u`, and fails on an import of any of the six or of a fused `sincosf`. Its live control is an import of `malloc`. The ci t3 job runs it, and `test-makefile-sane` checks that the T3 compile line reads the header first. On main it named `model.o`, `clef.o` and `cuda.o` on Linux, and `model.o`, `clef.o` and `metal.o` on an Apple M1.
  - The default build is unchanged: its objects and binary are byte-identical to main's. A T3 build's output can move in the last bits on a platform whose C library differs from `src/pmath.h` for these inputs. On an Apple M1 the four test fixtures score byte-identically before and after, on the CPU and on Metal.
  - Not changed here: the softmax's exp is still pmath's scalar double-precision one, which the compiler does not vectorize.
  - **`make cross-riscv64` builds again** (R6.86 follow-up). `src/instances.c` calls `fcntl` to keep the tray lock out of child processes (R9.5) but did not include `<fcntl.h>`, which POSIX declares it in. glibc's and macOS's `<sys/file.h>` bring it along, and musl's does not, so the riscv64 musl cross build stopped at "call to undeclared function 'fcntl'". The file now includes it. No CI job runs `cross-riscv64`, which is why nobody saw it.
