- **Q4_K and Q5_K quantization now writes llama.cpp's bytes at float32 near ties** (R4.56).
  - The cause: Runner's scale search accumulated each error term as `(w * diff) * diff`, and ggml's
    `make_qkx2_quants` and `make_qkx3_quants` write `w * (diff * diff)`. In float32 the last bit can differ, so at a
    near tie the strict `<` kept a different candidate scale.
    - The search now uses ggml's order. It serves the reference and weighted writers of Q4_K and Q5_K, and the
      weighted Q5_1.
  - On OLMo 3 7B Think, 157 of 12.46 million Q4_K super-blocks differed from bartowski's llama.cpp Q4_K_M. Two of
    them, one written without an importance matrix and one with, are now a fixture in `tests/test_quantize.c`.
  - Quality was unaffected: the two files' KL divergence from the reference could not be told apart.
  - Every existing byte-identity fixture against ggml (`tests/fixtures/quant-golden`) still matches byte for byte.
  - Known limits:
    - ggml changed `make_qkx3_quants`' search clamp after c1d0e7a, the version Runner's weighted fixtures pin.
      Where an input with no importance weight falls far outside its block's range, newer ggml writes a
      different code for it in weighted Q5_1. Runner matches c1d0e7a there.
    - The real-file check, a rebuilt OLMo 3 Q4_K_M against bartowski's, is still to run.
