- **The quantizer's docs say what is true: Runner ports ggml's algorithms, checks them on fixed inputs, and keeps
  its own evaluation order** (R4.56, R4.57).
  - Runner's Q4_K/Q5_K scale search sums each error term as `(w * diff) * diff`, where ggml writes
    `w * (diff * diff)`. At a float32 near tie between two candidate scales, the two can keep different ones.
    - On OLMo 3 7B Think that is 157 of 12.46 million Q4_K super-blocks against llama.cpp's file. The two files'
      KL divergence from the reference cannot be told apart.
    - Runner keeps its order, and its bytes do not change.
    - `src/quantize.c`, `MANUAL.md` (the `--quant` and `--imatrix` rows), the Makefile and the test output no
      longer promise byte identity with ggml. They say the golden fixtures check the ports on fixed inputs.
  - `tests/test_quantize.c` pins Runner's own bytes at two of those OLMo 3 near-tie blocks, one written without an
    importance matrix and one with. A change of order fails it.
  - The IQ3_XXS comparison with `llama-quantize` (`scripts/verify-device-writers-llama.py`) stays a correctness
    check of the port on its fixture, worded as a check.
  - Weighted Q5_1 no longer writes a far-off code for an input with no importance weight far outside its block's
    range (R4.57).
    - The scale search rounded such inputs with a trick that only rounds within about +-4 million. Beyond that it
      returns a wrapped value, so an input below its block's range could take code 31 where its nearest is 0.
    - Each level is now clamped to the code range before rounding. Within that range the result is the same as
      before.
    - Measured over 12 million searches in four shapes, including ggml's own #29804 groups:
      - the weighted error never changed;
      - every changed code lowered the plain error;
      - no other byte changed.
    - ggml made the same change (2923cf2862, for its #29804, an assertion). Runner takes it for the defect it
      removes in Runner.
  - Known limits: the golden fixtures stay pinned at ggml b10353 and c1d0e7a as checks of the ports. Weighted
    Q4_K and Q5_K recompute their codes from the packed scales, so R4.57 changes none of their bytes.
