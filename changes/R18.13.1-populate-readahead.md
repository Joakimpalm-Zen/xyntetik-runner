- **Account for backing-device kernel read-ahead in `test-populate`'s cached-cold Rss bar** (R18.13.1).
  - On Linux hosts whose backing device has a large `read_ahead_kb` (such as 2048 KiB on a dm/LVM volume), reading the GGUF header from an evicted file pulls one 2 MiB kernel read-ahead window (2.10 MB = 32.9% of the 6.39 MB fixture), which tripped the previous hardcoded `< 25%` Rss bar even though `cached` mode read zero cold pages beyond that window.
  - `tests/test_populate.c` now reads the fixture's backing-device `read_ahead_kb` without root via `/sys/dev/block/<maj>:<min>/queue/read_ahead_kb` (dm/LVM and whole disks), `/sys/dev/block/<maj>:<min>/../queue/read_ahead_kb` (partitions), and `/sys/class/bdi/<maj>:<min>/read_ahead_kb` (fallback for virtual filesystems), allows one read-ahead window on top of 25% (`Rss < data_sz / 4 + read_ahead_bytes`), and scales fixture `N_FF` if `read_ahead_kb > 2048` so one window stays at most one third of the fixture.
  - Added cross-platform unit checks (`test_cold_rss_bar`) verifying that 2.10 MB / 6.39 MB passes with a 2048 KB window while 60% and 90% still fail, and that 2.10 MB still fails on a 128 KB window.
