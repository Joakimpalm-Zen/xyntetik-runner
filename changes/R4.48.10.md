- **Inkling 2 Mini: LoRA attention training (SFT) and adapter serving on `inkling2_loop`** (R4.48.10).
  - **Limits first:** plain cross-entropy training of attention adapters (`blk.<b>.attn_{q,k,v,output}` across all physical blocks) and CPU adapter serving only. Teacher distillation (`--train-teacher`), DPO (`--train-dpo`), full-weight training (`--train-full`), and device training/serving (`device_kernels: null`, `host: "cpu"` in `--info adapter`) do not cover `inkling2_loop` yet and are each refused with an explicit sentence. Existing families' LoRA paths and `inkling2_loop` bare base forwards are unchanged; the real 23 GB checkpoint single-step run and gate (i) row re-check (`cbab5e99...`, `f6a913d6...`) run on a large-memory host before merge.
  - **Training backward pass (`src/inkling2_bwd.c`):** built as a serial float32 checkpoint-recompute DAG under `-fno-fast-math -ffp-contract=off` (`INKLING2_CFLAGS`), checkpointing every block application across both entry/exit passes and the looped middle passes. Every recomputed block output is verified bit-exact (`memcmp == 0`) against its saved forward output before reversing, accumulating gradients from every pass into the shared physical layer adapters (`ink2_lora`), including RMSNorms, depth attention across prior block outputs, top-k sigmoid-gated MoE experts, RoPE/NoPE Q/K/V, static plus global dynamic short convolutions, L2 clipping, learnable `log_tau`, relative position bias, `sink_proj`, gated `o_proj`, and the tied output head.
  - **Plumbing and serving:** `src/inkling2.c` and `src/inkling2_model.c` apply loaded adapters across physical layers while leaving the `lora == NULL` base forward untouched; `src/model.c`, `src/dpo.c`, and `src/main.c` admit `inkling2_loop` for SFT and serving via `lora_n_layer` / `lora_slot_dims` and refuse out-of-scope modes (`--train-teacher`, `--train-dpo`, `--train-full`). `src/inkling2_gguf.c` renames internal `stack_t` to `ink2_stack_t` so macOS strict builds cleanly alongside system `<stdlib.h>`, and `Makefile` builds `test-shared-weights` and `test-mlock` against `INKLING2_OBJS` (`INKLING2_CFLAGS`) while `src/inkling2_bwd.c` uses `-FLT_MAX`.
  - **Gates and tests:** `tests/test_inkling2_grad.c` verifies bit-exact recompute (plus a failing recompute-drift control), byte-deterministic gradients across `INK2_THREADS=1` and `4`, central finite differences (`96` coordinates, worst rel err `0`, cosine `1.000000`), whole/per-slot/per-block sign and Rademacher directional derivatives (`rel <= 0.00366` within the `0.005` gate), and five failing controls (drop looped pass 1, drop MoE router weight derivative, drop `sink_proj`, drop `relative_position_bias`, drop dynamic convolution `weight_proj`, each failing the `0.005` gate cleanly). `tests/test_inkling2_train.py` tests `--info adapter`, loss drop, `-t 1` vs `-t 2` determinism, `--save-every`/`--train-resume` parity, `runner attest replay`, zero-scale identity, adapted score shift, and scope refusals; unchanged `tests/test_lora_grad.c`, `tests/test_lora.py`, `tests/test_moe_lora.py`, and a baseline `moe4` trained adapter hash (`c6f99a31...`) confirm other families are untouched.
