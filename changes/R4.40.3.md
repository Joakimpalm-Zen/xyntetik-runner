- **On CUDA, several slots of a phi3 LongRoPE model past its original context share one device microbatch again, each column on its own factor set** (R4.40.3).
  - Recovers what R4.40.2 cost: on an RTX 5070 host with bartowski's Phi-3.5-mini-instruct Q4_K_M, four short requests at once (`--parallel 4 -c 8192 --kv q8`, 256 tokens each) decode at 348.6 tok/s aggregate, where R4.40.2 read 162.7 with the slots decoding one by one and the build before it 350.0 with every slot on the long set (351.5 in the same session as this reading; medians of three rounds).
  - How: each step's columns are ordered by factor set and the unchanged rope kernel runs once for each set present, over its own columns with its own table. A batch on one set issues the single launch it always did, so no other model's microbatch changes; the kernels and the PTX headers are untouched. A batch graph records the split between the sets and is captured again when it changes, as when a member's sequence grows past the original context.
  - Gated by `make test-cuda-batch-columns` (a batch on one set in reversed column order gives every sequence the same bits, at widths 2 to 4 on three fixtures) and `make test-cuda-longrope` (a batch with columns on both sets, and a member crossing the original context mid-batch, each column the bits of its sequence alone; a batch graph kept across the crossing is caught), both `scripts/cuda-gate.sh` steps.
  - The Apple GPU still decodes such slots one by one.
