- **The CPU route's default prompt batch rises from 64 to 256 on a machine of 6 GB or more** (R3.74), after R3.60 made a prompt's rows the same bytes at any width.
  - **Limits first:**
    - `512` is not measured on the CPU route, so the CPU route stops at `256`. `--gpu auto` on a CPU-only host of 12 GB or more already runs `512` unmeasured, filed as R3.75.
    - Windows is not measured yet (the RTX 5070 host's next session); the release waits for it.
    - Below 6 GB the CPU route keeps `64`.
  - **What changes:** `--gpu off`, `-ngl 0` and every session-image run (which runs on the CPU) take the RAM rule `--gpu auto` already uses, capped at `256`. One function, `model_batch_default`, serves the load and the preflight estimate.
  - **What does not:** the bytes. A session image or a KV snapshot written at `-b 64` continues with the same bytes under the new default, and the reverse (`tests/test_batch_default_widths.py`). `--gpu auto` is as it was.
  - **Measured:** on an RTX 5070 host's CPU, `-b 256` over `-b 64` read 1.0907x [1.0790, 1.1069] (Qwen3-4B, a 193-token prompt), with 18 to 28 MiB more memory.
  - **Measured on an Apple M1, 8 GB** (Qwen3-4B Q4_K_M, `--gpu off`, `-t 4`, strictly interleaved, 2026-11-18; the new default is 256 there):
    - 9 tokens: 1.0086 [0.9849, 1.0329], unresolved: no difference shown;
    - 204 tokens: 2.8691 [2.8135, 2.9258];
    - 1574 tokens: 2.5998 [2.5117, 2.6911].
    - Peak RSS was lower at the new default at every size (1573 against 1626, 1718 against 1785, 1811 against 1921 MiB).
    - On this host the weights were not resident (peak RSS 1.6 to 1.9 GiB for a 2.5 GiB file), so 2.6 to 2.9x is paging avoided, not compute. The compute-bound figure is the RTX 5070 host's 1.0907x.
  - **Pins:** a Mac CPU tier-smoke cell (lfm2.5-1.2b-instruct-q8_0) run at the new default matches its pin, which was recorded at `-b 64`.
  - `--help` and MANUAL give the default per route in one table; `--help` had said "free RAM", and the rule reads total RAM.
