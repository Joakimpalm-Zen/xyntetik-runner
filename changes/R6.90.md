- **A CUDA gate whose device is up and whose kernel module did not load now fails with the driver's log, instead of skipping as if there were no device; `make ptx` refuses embedded PTX that uses a feature above its pinned version** (R6.90).
  - Found in R8.24.1. A kernel took a 336-byte argument struct and read only part of it. nvcc 13 annotated the parameter loads with `.pragma "used_bytes_mask N"`, which needs PTX ISA 8.3. `scripts/embed-ptx.py` pins the embedded string to `.version 7.8`, so the driver's JIT rejected the whole module ("a PTX JIT compilation failed"). ptxas took the raw 9.0 PTX, so nothing at build time saw it. `test-train-gpu` then printed "no CUDA device, skipping (not passing)" and exited 0, and so would every gate that skips when no device engages. On a CUDA host a module that never loaded passed them all.
  - `src/cuda.c` keeps the first failed module load with the CUDA error and the driver's JIT log (loaded again with `cuModuleLoadDataEx`, on the failure path only), and prints each failure on stderr. The training module's failure used to print nothing. `gpu_module_failure()` returns it, and `tests/gate_gpu.h` turns it into a failure at the skip of every gate binary that has one: `test-train-gpu`, `test-lora-grad`, `test-mvt`, `test-mvcanon`, `test-prefill-bits`, `test-tc-tol`, `test-i8-tol`, `test-mv-tol`, `test-attn-tol`, `test-moe-tol`, `test-kv-tol`, `test-gpu-identity`, `test-batch-identity` and `test-cuda-teardown` skipped in silence before. `test-cuda-longrope` and `test-cuda-batch-columns` already exited 1 and now print the reason, and `test-cuda-kvfp4` loads its own module and already failed. Under `RUNNER_REQUIRE_GRAPH_CAPTURE=1`, the failure ends any process with exit 3, the runner's included. `make test`'s C gates (`test-gates-core`, `test-gates-batch`) and the `test-cuda-*` targets set the switch, and so does `tests/test_lora.py` for its runner. `make test-python` does not set it yet: its other GPU checks get the printed log and the old fallback.
  - `scripts/check-ptx-isa.py` decodes each embedded string and fails on a feature above its `.version`. It scans for the two features we know to need ISA 8.3, `used_bytes_mask` and `.b128`, with CUDA 13.0's ptxas naming the version for each. `make ptx` also assembles each string with the pinned ptxas for its target, which catches any feature, listed or not. `make test` runs the scan on the committed headers with a self-test, and the ptx-reproducible job runs the self-test against that ptxas: a used_bytes_mask pragma planted in a copy of each header must be caught.
  - `src/kernel_args.h` says how to keep kernel arguments: small and read whole, and checked on a CUDA host after `make ptx` to see that the embedded string loads.
  - **Gated:** red, then green, on an RTX 5070 (driver 610.88, Windows). `python3 scripts/check-ptx-isa.py --plant OUT src/kernels_ptx.h` writes the header with a used_bytes_mask pragma before its first parameter load. Built in place of `src/kernels_ptx.h`, on main `test-train-gpu` printed "no CUDA device, skipping" and exited 0. With this change it fails with exit 1 and the driver's log ("line 519; error: Feature 'used_bytes_mask' requires PTX ISA .version 8.3 or later"), and so does `test-mvt test.gguf`. Under the switch, `test-train-gpu` and `runner -m test.gguf` end with exit 3. On the R8.24.1 header that failed to load, the scan names lines 818586, 818733 and 818885, the three lines the driver's JIT rejected. The committed headers pass, and ptxas assembles both.
  - No effect on a module that loads, or on Metal and CPU builds.
