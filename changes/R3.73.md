- **On x86, MXFP4 weight rows decode with AVX2 and AVX-512, to the same bits** (R3.73).
  - The batched prompt pass decodes every MXFP4 weight row (the gpt-oss experts) to f32 before its matrix tile. On x86 that decode was C: a table lookup per weight behind a switch per 32 weights.
  - It is now a SIMD kernel. Each value is the same multiply on the same two operands as the C decode, so the output bytes are unchanged. That is checked at every code and every one of the 256 exponents, at x86-64-v3 and v4, and under the runner's own `-ffast-math` flags.
  - Measured so far on one hosted x86 runner (Xeon 6975P-C, 4 vCPU, the R3.60 bench): the decode of a 2,880 x 2,880 expert is 3.3x faster per weight (1.03 to 0.31 ms), and the 64-column tile product 11% faster (5.46 to 4.83 ms). The lab read on gpt-oss-120b's host is pending.
