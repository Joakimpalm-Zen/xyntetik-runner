- **A Gemma-4 E-series prompt's bits no longer depend on `-b` or on a cache on the CPU** (R4.48.34).
  - The per-layer embeddings' projection runs before the layers. It now takes the prompt's batch route at every
    width, as the layers have since R3.60. Before, a feed pass of 1 to 7 rows took the native dot: a prompt's short
    tail, a cached prefix continued by a few tokens, or a repeated prompt's last token, fed again alone. So `-b 64`
    and `-b 512` stored different K/V rows and gave different logits, as did a cached prefix's continuation against
    the same prompt on a fresh slot.
  - So on CPU-only runs at `-b` 2 or more, an E-series prompt with a pass of 1 to 7 rows changes its bits once. That
    covers a prompt under 8 tokens, a 1-7 token tail past a `-b` boundary, and a continued or repeated prompt. They
    change to the bits the same prompt gives at any width, read fresh. A prompt fed only in passes of 8 or more rows
    keeps its bits, and so does decode.
  - R3.60's identity gate now runs on an E-series fixture with per-layer embeddings.
  - A new test seam, `RUNNER_TEST_REC_DUMP=1`, prints a recurrent model's state after every prompt feed. The qwen4exp
    fork test uses it to check the state word for word on the CPU, beside its logprobs.
  - On CUDA, R3.60's identity is not declared. The fork test's CUDA arm now asks for the same tokens, logprobs
    within 1e-5 and the state within a relative 5.4e-4, and `docs/kernel-routes.md` says a continued prompt may
    round differently on a GPU run.
