- **More schemas compile, and a Metal split that cannot stay resident is no longer taken** (R2.17, R3.67).
  - **Annotation-only schema keywords** (R2.17). Runner refused any schema keyword it did not know, where a JSON Schema validator ignores annotations. A named list of annotation-only keywords is now accepted and ignored: `id` (beside `$id`), `readonly` (readOnly's misspelling), vendor extensions `x-*`, and Snowplow's self-describing `self` header at a schema's root. Any keyword that could constrain a value and is not on the list is still refused: Runner never accepts a constraint it does not enforce.
    - On JSONSchemaBench's 8,108 schemas, the ones Runner compiles went from 2,287 (28.2%) to 2,791 (34.4%).
    - A nested `id` or `$id` over a `$ref` is now refused, `$id` included, since it would move the reference's base and Runner resolves every local reference against the document root.
  - **A Metal partial split is priced against the whole machine** (R3.67). On unified memory the KV cache Metal allocates for the whole context and every layer stays resident beside the weights, where the CPU alone pages its KV in as it is used. The split check counted only the weights against available RAM and guessed the rest, so on an 8 GB Mac Phi-3.5-mini at `-c 8192` took a split that swapped and generated at 0.09 to 0.5 tok/s. The split is now taken only when the weights, the whole-context KV and a margin fit in the RAM available; otherwise the load stays on the CPU and prints what it would hold against what is available. `--gpu-layers N` still forces a split.
    - Phi-3.5-mini Q4_K_M at `-c 8192` on an 8 GB Mac now loads on the CPU and generates at 6.6 to 6.7 tok/s, the same as `--gpu off` (6.7 to 7.3) in interleaved warm runs.
    - Not measured: a larger Mac where the device's working set binds before RAM does, the case a split exists for.
    - Phi-3's LongRoPE factor tensors and llama3's `rope_freqs` are no longer counted as weights the device must hold; the host folds them into the rope frequencies at load.
