- **Route line, receipts, `--verify`, `--doctor`, provenance, and `--train-kv-f32` now see Inkling 2's real K/V cache type (`f32` or `q8`) instead of `f16` (R4.48.32).**
  - **Root cause:** `inkling2_loop` is the only architecture in `src/arch.h` that bypasses `bind_kv_layout()` and initializes its own cache in `model_inkling2_runtime()` (`src/inkling2_model.c`). `model_inkling2_runtime()` picked its real storage format (`INK2_KV_F32` by default or on fallback, `INK2_KV_Q8` under `--kv q8`, or `INK2_KV_RT` under `RUNNER_INKLING2_TEST_KV_RT=1`) in `r->c.kv` and printed it on the load line (`K/V q8` / `K/V f32`), but left `model_t`'s `kv_q8`, `kv_f32`, `kv_fp4`, and `kv_split` flags all `false`. Every consumer reading `model_kv_name(m)` or `m->kv_*` (`route_collect()` -> `--score`'s `score: route` JSON and `model_route_hash()`, `--record` / `--receipts` / `--verify`, `--doctor`, `GET /v1/runner/provenance`, `RUNNER_DEBUG_VRAM`, `engine.c`'s `model_key`, and `--train-kv-f32`) therefore fell through to `model_t`'s zero-initialized `"f16"` default.
  - **Fix:** `model_inkling2_runtime()` now mirrors the initialized cache format `r->c.kv` onto `model_t` (`m->kv_q8 = (r->c.kv == INK2_KV_Q8)`, `m->kv_f32 = (r->c.kv != INK2_KV_Q8)`, `m->kv_fp4 = m->kv_split = false`), so every surface reports the cache actually in use (`f32` or `q8`, including when unsupported `--kv` flags or CUDA gating fall back to `f32`).
  - **Legacy `--verify` compatibility rule (`src/main.c`):** every released Inkling 2 build through `1.22.0` ran `f32` K/V only and stamped `"kv":"f16"` on its receipts (including all 421 published receipts in `inkling2-claims-records-1.22.0.tar.gz`). `run_verify_replay()` accepts legacy `"f16"` as matching Inkling 2's own `f32` cache ONLY when the receipt's `"runner"` version parses strictly as `<= 1.22.0` (`runner_ver_le_1_22_0()`). Receipts with `"runner"` `> 1.22.0` (or unparseable versions) stay strictly verified against `"f32"` or `"q8"`.
  - **Session `--resume` advice (`src/session.c`):** resuming a legacy `<= 1.22.0` Inkling 2 session image (`kv_type="f16"`) stays loudly refused (`model_key` now separates Inkling `f32` vs `q8`, and Inkling 2 images wrote 0 K/V bytes because `m->n_layer == 0`), and `session_key_mismatch()` now reports that `inkling2_loop` only supports `f32` and `q8` instead of the impossible `"resume with --kv f16"` advice.
  - **`--train-kv-f32` behavior (`src/main.c:5555`):** `--train-kv-f32` now admits Inkling 2's default `f32` cache (where `!rt->m.kv_f32` previously refused it falsely) and records `"kv_cache":"f32"` in `.train.json`, while still refusing `--train-kv-f32 --kv q8`.
